# Google Drive 백엔드 자동 백업 전환 계획

작성일: 2026-06-26

## 목적

현재 Google Drive 백업은 브라우저에서 직접 OAuth 인증을 수행하는 방식이다. 이 구조에서는 새로고침할 때 Drive 접근 토큰이 사라지고, 시스템 로그인 복구 후 자동 연결이 다시 실행되면서 Google 로그인 창이 반복해서 뜰 수 있다.

목표는 다음과 같다.

- 새로고침 시 Google 로그인 창 반복 표시 제거
- 사용자가 화면을 열어두지 않아도 자동 백업 가능
- 백업 실패 기록, 재시도, 복원 관리 기반 마련
- Google 토큰을 브라우저 저장소가 아니라 서버 측에서 안전하게 관리

## 권장 구조

권장 방식은 Firebase 기반 백엔드 구조다.

- Firebase Authentication: 기존 시스템 로그인 사용
- Firestore: 백업 설정, 상태, 백업 이력 저장
- Firebase Cloud Functions: Drive 연결, 즉시 백업, 정기 백업, 복원 처리
- Google Drive API: 백업 파일 저장
- Secret Manager 또는 암호화 저장소: Google OAuth refresh token 보관

## 1단계: 현재 팝업 문제 완화

가장 먼저 새로고침 때 Google 로그인 창이 자동으로 뜨지 않게 한다.

변경 방향:

- 시스템 로그인 성공 직후 Google Drive 자동 연결을 바로 실행하지 않음
- `Drive 연결` 버튼을 눌렀을 때만 Google OAuth 창 표시
- 자동 백업은 Drive 연결이 살아 있는 동안만 실행
- 연결이 없으면 “Drive 연결 필요” 상태만 표시

기대 효과:

- 새로고침 시 로그인 팝업 반복 제거
- 기존 수동 Drive 백업 기능 유지
- 백엔드 전환 전에도 사용성 개선

## 2단계: 백엔드 백업 구조 설계

사용자는 최초 1회 Google Drive 권한을 승인하고, 이후 서버가 백업을 실행하는 구조로 전환한다.

주요 흐름:

1. 사용자가 시스템 관리에서 `Drive 연결` 클릭
2. Google OAuth 승인
3. 서버가 refresh token을 안전하게 저장
4. Firestore에 백업 설정 저장
5. Cloud Functions가 정해진 주기에 Google Drive 백업 실행

## 3단계: 저장 데이터 정의

Firestore에는 민감하지 않은 설정과 상태만 저장한다.

예상 필드:

- 회사 또는 테넌트 ID
- Drive 폴더 ID
- Drive 연결 계정 이메일
- 자동 백업 사용 여부
- 백업 주기
- 마지막 백업 시각
- 마지막 백업 성공 여부
- 최근 실패 사유
- 백업 파일 목록 메타데이터

주의:

- Google refresh token은 일반 Firestore 문서에 평문 저장하지 않는다.
- Secret Manager 또는 별도 암호화 저장 방식을 사용한다.

## 4단계: Cloud Functions 추가

필요 함수:

- `connectDrive`: Google OAuth 승인 후 서버용 토큰 저장
- `disconnectDrive`: 저장된 Drive 연결 정보 해제
- `runBackupNow`: 사용자가 즉시 백업 실행
- `scheduledBackup`: 정해진 시간마다 자동 백업 실행
- `listBackups`: 최근 백업 파일 목록 조회
- `restoreBackup`: 선택한 백업 파일로 복원

백업 파일명 예:

```text
mes-data-20260626-093000.json
```

## 5단계: 프론트 화면 수정

시스템 관리 > Google Drive 저장 화면을 정리한다.

표시 항목:

- 연결 상태
- 연결 계정
- 자동 백업 사용 여부
- 백업 주기
- 마지막 백업 시간
- 최근 실패 사유

버튼 구성:

- Drive 연결
- 연결 해제
- 지금 백업
- 백업 목록 새로고침
- 복원

## 6단계: 자동 백업 정책

권장 정책:

- 기본값은 자동 백업 꺼짐
- 사용자가 자동 백업을 켜면 서버 스케줄러가 실행
- 실패 시 이력에 기록
- 필요 시 관리자 알림으로 확장
- 최근 30개 또는 최근 30일 기준으로 백업 보관

## 7단계: 검증 항목

필수 검증:

- 새로고침해도 Google 로그인 창이 자동으로 뜨지 않는지 확인
- 수동 Drive 연결이 정상 동작하는지 확인
- 즉시 백업이 정상 생성되는지 확인
- 서버 자동 백업이 스케줄대로 실행되는지 확인
- Drive 폴더와 파일 생성 여부 확인
- 백업 복원 전후 데이터 비교
- 권한 없는 사용자가 백업/복원 기능을 사용할 수 없는지 확인

## 추천 진행 순서

1. 새로고침 시 Google 로그인 창 반복 문제를 먼저 막는다.
2. 기존 프론트 Drive 백업은 수동 연결 방식으로 안정화한다.
3. Firebase Cloud Functions 기반 백엔드 백업을 추가한다.
4. 서버 백업이 안정화되면 프론트 직접 Drive 백업은 보조 기능으로 남긴다.

## 결론

자동 백업을 위해 현재처럼 새로고침마다 Google 로그인 창이 뜨는 상태를 유지할 필요는 없다. 단기적으로는 자동 연결을 완화하고, 장기적으로는 서버가 백업을 담당하는 구조로 전환하는 것이 가장 안정적이다.
